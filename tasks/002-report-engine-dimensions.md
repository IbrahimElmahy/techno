## المشكلة

نظام a5 عنده التقارير دي (وكلها ناقصة عندنا):

```
صنف = مندوب = يوم      مندوب = صنف = يوم      فئة = مندوب = فترة
صنف = مندوب = شهر      مندوب = صنف = شهر      مندوب = فئة = فترة
اصناف = عملاء = يوم    عملاء = صنف = يوم      فئة = مندوب = شهر
اصناف = عملاء = شهر    عملاء = صنف = شهر      مندوب = فئة = شهر
فئات = عملاء = فترة    عملاء = فئة = فترة     فئة = مندوب = يوم
فئات = عملاء = شهر     عملاء = فئة = شهر      مندوب = فئة = يوم
فئات = عملاء = يوم     عملاء = فئة = يوم
```

**دول مش عشرين تقرير. ده تقرير واحد بنمط `بُعد × بُعد × فترة`.**

ومحركنا `backend/src/lib/trade_reports.py` عاجز عنهم لسببين بس:

```python
GROUPS = ("none", "party", "item", "warehouse")   # سطر 39
```

1. **`group_by` بُعد واحد** — مايقدرش يعمل «صنف **و** مندوب» مع بعض
2. **مافيش بُعد «مندوب» ولا «فئة»، ومافيش تجميع زمني (يوم/شهر)**

> ⚠️ **متكتبش عشرين دالة.** لو عملت كده هتبقى عشرين نسخة من نفس الكود، وأي إصلاح
> في حساب الهامش هيتعمل عشرين مرة. الشغل كله في ملف واحد.

## التصميم المطلوب

### ١) `group_by` يبقى **قايمة أبعاد** مش بُعد واحد

```python
DIMENSIONS = {
    # بُعد ← (كيف نستخرج مفتاحه، وكيف نسمّيه)
    "party":     ...,   # عميل / مورد   (موجود)
    "item":      ...,   # صنف           (موجود)
    "warehouse": ...,   # مخزن          (موجود)
    "rep":       ...,   # مندوب          ← جديد
    "category":  ...,   # فئة الصنف      ← جديد
    "day":       ...,   # اليوم          ← جديد
    "month":     ...,   # الشهر (YYYY-MM) ← جديد
    "year":      ...,   # السنة          ← جديد
}
```

المفتاح بيتركّب من الأبعاد المطلوبة بالترتيب:

```python
key = tuple(DIMENSIONS[d].key(r) for d in dims)
```

فـ«صنف = مندوب = يوم» تبقى `group_by=["item", "rep", "day"]` — وخلاص.

**التوافق مع القديم إجباري:** `group_by="party"` (نص) لازم يفضل شغّال زي ما هو.
حوّل النص لـ`[value]` جوّه، و`"none"` لـ`[]`. الشاشات القايمة بتستعمله دلوقتي.

### ٢) الصف الراجع

كل صف لازم يشيل **قيمة كل بُعد لوحدها**، مش نص ملزوق:

```python
{"dims": {"item": "سخان 30 لتر", "rep": "احمد تركى", "day": "2026-08-27"},
 "item_id": 412, "rep_id": 53,          # الـids عشان اللينكات
 "quantity": "...", "amount": "...", "profit": "...", "document_count": 7}
```

❌ **متعملش** `"label": "سخان 30 لتر — احمد تركى — 2026-08-27"`.
النص الملزوق مايتفرزش ولا يتفلتر ولا يتعمل منه عمود.

### ٣) `_collect` يطلّع البُعدين الجداد

لكل نوع مستند في `_collect` ضيف للصف:

```python
"rep_id": doc.rep_id,
"category": items[ln.item_id][?] ,   # وسّع _names عشان ترجّع الفئة كمان
```

`_names()` دلوقتي بترجّع `(code, name, unit_of_measure)` للصنف —
**وسّعها للفئة**، ومتعملش استعلام لكل صف (المصيدة دي وقعنا فيها، `HANDOFF.md` قسم ٦).

### ٤) المجاميع الفرعية

تقارير a5 بتوري **مجموع لكل بُعد أول** (مجموع المندوب ومجموع كل صنف تحته).
رجّع `subtotals` مبنية من نفس الصفوف المسطّحة — **متحسبهاش تاني بطريقة مختلفة**،
عشان المجموع الفرعي والكلي مايختلفوش. نفس مبدأ التعليق الموجود في السطر ٢١٦.

## الواجهة

### الباك إند

`backend/src/api/trade_reports.py` — `group_by` يقبل قايمة
(`?group_by=item&group_by=rep&group_by=day` أو مفصولة بفواصل).
**تحقّق من الأسماء** وارفض المجهول برسالة بتقول الأبعاد المتاحة.

### الفرونت

شاشة **واحدة** بمنتقي أبعاد — مش عشرين شاشة.

- المستخدم يختار لحد ٣ أبعاد بالترتيب
- الأعمدة بتتولد من `dims` اللي رجعت
- ومداخل القايمة تبقى **presets** على نفس الشاشة، بالظبط زي `/ops-reports?view=…`:

```ts
{ key: '/trade-reports?doc=sale&dims=item,rep,day', label: 'صنف = مندوب = يوم', ... }
```

كل الأسماء العشرين تتحط في `navigation.ts` تحت «تقارير المبيعات» — **بأسماء a5 حرفياً**
عشان اللي جاي من نظامهم يلاقي اللي بيدوّر عليه بنفس الاسم.
