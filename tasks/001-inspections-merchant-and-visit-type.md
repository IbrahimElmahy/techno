## 🔴 اقرا ده قبل أي حاجة — الغلطة اللي هتقع فيها لو مقريتش

في `Wh_TechnicalVisits` عمود `MerchantsID` بيشاور على `wh_Merchants` (٤٤٣ تاجر).
الإغراء إنك تكتب سكربت يدوّر على العميل بكود `ERP-M-{MerchantsID}`.

**ده هيربط ١١٤ تاجر بس من ٤٤٣ — ويسيب ٧٤٪ فاضيين من غير ما يشتكي.**

ليه؟ `import_erp_parties.py` سطر ١٧٧:

```python
target = by_code.get(code) or by_name.get(_norm(name))
```

التاجر اللي اتطابق **بالاسم** مع عميل a5 موجود اتحدّث في مكانه و**احتفظ بكود a5**.
و`Customer.code` عمود واحد `unique` — مافيش مكان تاني يتخزّن فيه رقمه في نظامهم.
يعني رقم الـ`MerchantsID` بتاعه **مش موجود عندنا خالص**.

المطلوب: **حلّ المطابقة بالكود وبالاسم مع بعض**، بنفس دالة `_norm()` اللي الـimporter
نفسه استعملها — أي حاجة تانية هتدّي نتيجة مختلفة.

**وممنوع تسيب صف مش متطابق في صمت.** اطبع العدد: اتربط كام، وفضل كام، وليه.

### والتاجر اللي مااتطابقش = غلطة مطابقة، مش طرف جديد

اقرا «دورة الكوبون» في `HANDOFF.md` قسم ٤٫٣٥. الخلاصة: الكوبون أصلاً جاي من نقاط بيع
اتعملت **للتاجر**، يعني كل تاجر في ما بعد البيع **لازم** يكون موجود في نظام البيع.
تاجر مالوش مقابل شيء مستحيل منطقياً.

فلو طلع عندك تجار مش متطابقين:
- ⛔ **متعملهمش عملاء جداد** — ده بيعمل نسخة تانية لنفس الراجل، وهي المشكلة اللي الدمج
  اتعمل عشانها أصلاً.
- ✅ اطبع أسماءهم كلها في تقرير للمراجعة اليدوية.
- ✅ جرّب تحسّن المطابقة الأول: شيل الألقاب، وحّد «عبد»/«عبدالـ»، شيل المسافات المكررة،
  وجرّب المطابقة الجزئية (اسم التاجر جوّه اسم العميل أو العكس) — واعرض المقترحات
  للمراجعة، **متطبّقهاش أوتوماتيك**.

`purchase_shop` (النص) **يفضل موجود** كنسخة احتياطية للصفوف اللي مالهاش تاجر متطابق.

## الخطوات

### ١) التصدير من SQL Server — `SELECT` بس

ملفين. اكتبهم في `C:/pgtmp/` على السيرفر وصدّر لـ`C:/pgtmp/erp/`.

**(أ) `exp_merchants.sql`** — خريطة رقم التاجر → اسمه وتليفونه:

```sql
SET NOCOUNT ON;
SELECT CAST(m.ID AS VARCHAR) + '~'
  + REPLACE(REPLACE(ISNULL(m.Name_Ar,''),CHAR(13),' '),CHAR(10),' ') + '~'
  + REPLACE(REPLACE(ISNULL(NULLIF(m.Mobile1,''), ISNULL(m.Phone,'')),
            CHAR(13),' '),CHAR(10),' ')
FROM wh_Merchants m;
```

**(ب) `exp_vfix.sql`** — الأعمدة الناقصة على كل معاينة:

```sql
SET NOCOUNT ON;
SELECT CAST(v.ID AS VARCHAR) + '~'
  + CAST(ISNULL(v.MerchantsID,0) AS VARCHAR) + '~'
  + REPLACE(REPLACE(ISNULL(LTRIM(RTRIM(v.PurchaseStore)),''),CHAR(13),' '),CHAR(10),' ') + '~'
  + CASE WHEN ISNULL(v.IsMarma,0) = 1 THEN N'مرمة' ELSE N'معاينة' END + '~'
  + CAST(ISNULL(v.CountPrint,0) AS VARCHAR)
FROM Wh_TechnicalVisits v;
```

> ⚠️ الملفين دول **مالهمش عربي في شرط `WHERE`** فعادي يتكتبوا UTF-8.
> لو احتجت تضيف `LIKE N'%عربي%'` — **متكتبش الملف UTF-8**، sqlcmd بيقراه غلط
> وبيرجّع صفر صفوف من غير رسالة خطأ. اعمل الفلترة في بايثون.

### ٣) سكربت الـpatch

`backend/src/scripts/fix_inspection_merchants.py` — **idempotent، دراي‑رن افتراضي،

المنطق:

1. اقرا `merchants.tsv` → `{erp_merchant_id: (name, phone)}`
2. ابني خريطة الحل مرة واحدة (مش استعلام لكل صف):
   ```python

   by_code = {c.code: c for c in customers if c.code}
   ```

## ⛔ الحالة (مقبولة / مرفوضة) — متلمسهاش

`InspectionStatus` ده **اختراعنا إحنا**، مش من نظامهم. اتفحصت أعمدتهم كلها:

| العمود | القيم | الحكم |
|---|---|---|
| `OutRange` | ٥٩٢ زيارة برّه النطاق الجغرافي | إشارة مراجعة حقيقية، بس **مش** قبول/رفض |
| `ResponseCode` | ٠ / ١ / ١٩٠٣ | كود رد المزامنة |
| `Code` | ٢٦٢١ قيمة مميزة على ١٠٬٩٢٧ صف | مش رقم شهادة |
| `VisitType` bit | ٢٨٨ / ١٠٬٦٣٩ | معناه مش واضح |

**مافيش عمود قبول/رفض في نظامهم.** السؤال متبعت للمستخدم ولسه مافيش رد.

الغلطة دي اتعملت قبل كده: اختراع تصنيفات عملاء (معرض/شركة/مؤسسة) مالهاش وجود في a5،
والمستخدم رفضها واتشالت. **متكررهاش.** سيب `status` زي ما هو لحد ما المستخدم يجاوب.
