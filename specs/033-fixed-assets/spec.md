# الأصول الثابتة — مقارنة مع Odoo وتصميم النظام

المرجع: موديول `account_asset` في Odoo (Accounting ‣ Assets).

## ١. توزيع الشاشات

| Odoo | النظام | المكان |
|---|---|---|
| Accounting ‣ Assets (قائمة + فورم) | **الأصول الثابتة** | إدارة الحسابات ‣ الأصول الثابتة ‣ الأصول |
| Configuration ‣ Asset Models | **فئات الأصول** | إدارة الحسابات ‣ الأصول الثابتة ‣ فئات الأصول |
| Reporting ‣ Depreciation Schedule | **جدول الإهلاك** (تقرير) | إدارة الحسابات ‣ الأصول الثابتة ‣ جدول الإهلاك |
| ترحيل آلي بالـcron | زر **ترحيل الإهلاك** في القائمة بنافذة معاينة | قائمة الأصول |

## ٢. فورم الأصل

| Odoo | النظام |
|---|---|
| شريط الحالة Draft → Running → Closed | نفس الشريط: مسودة → قيد التشغيل → مغلق، و«موقوف» كحالة جانبية |
| Smart buttons: Journal Entries، Bills | زر **القيود** (عدد) يفتح قايمة القيود، وزر **المستند المصدر** (فاتورة شراء أو سند مصروف) |
| أزرار: Confirm، Pause، Resume، Modify Depreciation، Sell or Dispose، Set to Draft | تأكيد، إيقاف، استئناف، **تعديل الإهلاك**، **إعادة تقييم** (زيادة/تخفيض)، **بيع أو استبعاد**، إرجاع لمسودة |
| تبويب Depreciation Board (مرحل/مخطط) | تبويب **جدول الإهلاك**: الشهر، القسط، المجمع، القيمة الدفترية، الحالة (مرحل/مستحق/مخطط) والقيد |
| Chatter | تبويب **السجل** (كل عملية بتاريخها والمستخدم) |
| الحقول: Original value، Acquisition date، Not depreciable value، Method، Duration، Prorata، Accounts | القيمة الأصلية، تاريخ الشراء، القيمة التخريدية، الطريقة، المدة/النسبة، احتساب جزء الشهر، الحسابات الثلاثة |
| Import existing asset: Depreciation already done | **إهلاك سابق** + **بداية الإهلاك على النظام** |

## ٣. المنطق

| Odoo | النظام |
|---|---|
| Linear / Degressive / Degressive then Linear | القسط الثابت / المتناقص / المتناقص ثم الثابت / مجموع أرقام السنين / بدون إهلاك |
| الباقي يتوزع على الفترات الباقية | القسط الثابت = (القابل للإهلاك − المهلك) ÷ الشهور الباقية، ويتعاد حسابه بعد أي تعديل |
| Prorata temporis (يومي) | خيار «احتساب جزء الشهر الأول» بالأيام، والباقي يتنقل لآخر شهر |
| Modify: تغيير المدة/القيمة مع سبب | تعديل الإهلاك (طريقة، نسبة، شهور باقية، تخريدية) بسبب، وإعادة التقييم بقيد |
| Gross increase ← أصل فرعي | الزيادة بتتضاف لتكلفة نفس الأصل: مدين الأصل / دائن الحساب المقابل |
| Decrease ← قيد إهلاك | التخفيض: مدين خسائر هبوط قيمة / دائن مجمع الإهلاك |
| Sell / Dispose: قيد بالربح أو الخسارة | نفس القيد: دائن الأصل بالتكلفة، مدين المجمع، مدين النقدية بثمن البيع، والفرق ربح أو خسارة |
| Asset from vendor bill (حساب أصل ثابت على السطر) | فاتورة شراء نوعها «أصول» وسند مصروف «شراء أصل ثابت» بيعملوا الأصل لوحدهم |
| Model: Create asset = Draft / Validate | خيار في الفئة «تأكيد تلقائي»؛ لو مقفول الأصل بيتعمل مسودة |
| حسابات لكل Model | كل فئة ليها حساب أصل وحساب مجمع إهلاك لكل فرع، تحت مجموعات a5 الموجودة |
| Expense account per model | مصروف إهلاك **صناعي** للأصول الإنتاجية و**إداري** للباقي |
| Cron يرحل الأقساط المستحقة | «ترحيل الإهلاك حتى شهر» بيرحل كل الشهور المستحقة لكل الأصول، قيد لكل فرع في كل شهر |

## ٤. جدول الإهلاك (تقرير)

نفس أعمدة Odoo لفترة من–إلى، مجمّع بالفئة:

| التكلفة | | | | الإهلاك | | | | |
|---|---|---|---|---|---|---|---|---|
| أول المدة | إضافات | استبعادات | آخر المدة | أول المدة | إضافات | استبعادات | آخر المدة | القيمة الدفترية |

## ٥. اللي مختلف عن Odoo عن قصد

- **مافيش قيود مسودة مستقبلية:** Odoo بيعمل قيد مسودة لكل قسط جاي. النظام بيحسب الجدول وقت العرض وبيرحل وقت الترحيل بس، فمافيش آلاف القيود المعلقة في الدفاتر.
- **الترحيل يدوي بزر** بدل cron، لأن العميل بيقفل الشهر بإيده.
- **الفترة شهرية بس** (Odoo بيسمح بسنوية). النسبة السنوية بتتحول لقسط شهري.
